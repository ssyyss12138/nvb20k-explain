01

模型架构

骨架是 Qwen3 式 decoder-only Transformer：pre-norm + RMSNorm + QK-Norm + RoPE + 因果自注意力 + ReLU² MLP。 四档同架构，只变宽/深/头数（head_dim 恒为 128）。这一节先不看压缩和表，只看骨架本身。

02

Token 压缩技术：16 个 token → 1 个位置

压缩只发生在层栈的中段：前 20% 层逐 token 算，中间约 60% 层在“16 个 token 合成 1 个位置”的短序列上算，后 20% 层再回到逐 token。 它是一次序列长度上的下采样（3072 → 192），不是特征维降维（h 不变）。

为什么压

注意力核心开销 ∝ 序列长度的平方。中段把长度 ÷16：线性层计算 ÷16，注意力核心 ÷256；同样的参数与算力可以多看几倍 token。

压完是什么

得到 192 个“摘要位置”，每个位置包含原序列连续 16 个 token 的信息；中段在这些位置上做全局注意力。

代价

一个位置代表 16 个 token，是有损压缩。靠前后的全长层、展开的内容门控、以及压缩前的残差来补细节。

① 怎么压：拼接 + 线性投影

在第 s 层（前段最后一层）之后，先保存一份全长残差 a = x（[B, 3072, h]），然后：

x_pad = 序列前面补 15 个零向量 # [B, 3072+15, h] 每 16 个连续向量拼接成一个 16h 向量 # [B, 192, 16h] z = W_down · concat # [B, 192, h] W_down : [h, 16h]（无 bias 的线性层） 1e19：h = 1152，16h = 18432

所以压缩后的第 j 个位置，正好包含原序列 token 16j−15 … 16j 这 16 个 token 的隐状态。第 0 块前面是补的零。窗口互不重叠、严格因果。

一个具体数字（1e19）

原序列3072
压缩后192
每个位置拼接16 × 1152 = 18432
W_down18432 → 1152
窗口 jtoken 16j−15 … 16j

训练/评测序列长度都是 16 的整数倍；不是整数倍时末尾补零，只影响最后一个位置。

② 压缩后“位置”怎么定：不是新 token id，是块号 j

token id 不变。token id 由分词器决定（BPE 词表 49152），压缩不会重新编号，也不会生成新的 token id；被压缩的是隐状态序列。

压缩后得到 192 个位置，位置编号是 j = 0 … 191（块号）。每个位置 j 对应原序列的 16 个 token，但它在中段里只占 1 个位置：

中段 RoPE 位置 = 块号 j（0 … 191） 中段因果 mask = 192 × 192 的因果矩阵 中段 attention 的“序列长度” = 192

所以压缩改变的只是“序列有多长、每个位置代表多少 token”，没有改变 token 本身的 id。

③ 怎么恢复：上投影 + 按块切片 + 内容门控 + 残差

中段算完后，把 192 个位置展开回 3072 个 token：

u = W_up · z # [B, 192, 16h] reshape 成 [B, 192, 16, h] token t 取第 ⌊t/16⌋ 块的第 (t mod 16) 片： u_t = u[⌊t/16⌋, t mod 16] g_t = 2σ( W_out·W_in·RMSNorm(a_t) + β_{t mod 16} ) # 秩 64 x_t = a_t + g_t ⊙ u_t # 加回压缩前残差

关键点：展开不是简单复制。块内 16 个 token 共享同一个摘要，但每个 token 用自己的门 g_t 决定读回多少；再与压缩前的残差 a_t 相加，所以中段只是“残差流里的一个低分辨率处理块”。

为什么能恢复出细节

  • 压缩前的全长残差 a_t 一直在，每个 token 的原始信息不会丢；
  • 内容门 g_t 由当前 token 自己的全长隐状态算出，逐 token 决定读多少摘要；
  • 后段 20% 的层回到全分辨率，继续做逐 token 的注意力与 MLP。

这就是“U-Net / Hourglass”式的结构：下采样 → 低分辨率处理 → 上采样 → 跳连（残差）。

④ 压缩 / 展开总图

因果性：块 j 的摘要只包含 token ≤ 16j，而它展开服务的 token 是 16j … 16j+15——每个 token 读到的信息都不含未来。 注意窗口终点 16j 与展开起点 16j 是同一个 token：摘要恰好止于该块第一个输出 token 自己。
03

VE 表：按当前 token 查表，加进注意力 V

VE = Value Embeddings。一句话：给每个 token 的 Value 加一条“我是谁”的可学习旁路。 它不改 q/k、不改注意力分数，只改被注意力聚合的 v；查表没有矩阵乘，是“免费容量”。

干什么用

注意力的输出是 Σ softmax(q·k)·v，v 才是真正被加权求和的内容。标准 Transformer 的 v 完全来自 W_v·h；VE 额外查出一段向量加进 v。

直觉：哪怕注意力权重很分散，每个 token 的 value 里也始终带着自己的身份/类型信息，模型不用全靠 W_v 去记。

用在哪

每一层注意力内部：V 的线性投影之后、分头与因果注意力之前。中段缩短时只在块尾 token 处查（每 16 个 token 一次）。

和输入嵌入 E 的区别：E 只出现在输入残差流（x⁰）；每一层的 V 是“当前隐状态 × W_v”重新算出来的；VE 是另外查表加到 V 上——三者不是同一个东西。

② 怎么查：行号就是 token id

普通的嵌入查表，不是哈希：

给定位置 t 的 token id x_t，以及它所在的层 i： 1. 找到层 i 绑定的表 g 2. 取表 g 的第 x_t 行 3. 得到一个 kv 维向量 前后全分辨率层：每个 token 都查 中段缩短层：只在块尾 token（第 16j 个）查一次，整块共用

查出来的向量是 kv 维（3e17 是 640，1e19 是 1152）；若要做逐 KV 头门控，就 reshape 成 [KV 头数, 128]。没有哈希、没有碰撞、没有指纹校验。

③ 一个具体例子

3e17 档、token id = 4471、位于第 0 层：

第 0 层绑定表 0（与第 17 层共用） → 取表 0 的第 4471 行：一个 640 维向量 → reshape 成 5 个 KV 头 × 128 → 每头乘门控 g（初始 1） → 按 λ₁ 加进该 token 的 v

如果这个 token 同时被 VE 和 NVE 命中，v 里会同时加上两路查表向量（分别用 λ₁、λ₂/λ₃ 加权）。

④ 怎么训练更新

初始化

表：N(0, 0.02) 随机初始化，和输入嵌入一样；λ：0.5；门控：零初始化（初始 g = 1）。

反向传播

梯度从注意力输出 → v → 反传到被查到的那些行；本 batch 没出现过的 token 行不更新（稀疏行更新）。因为首尾层共用表，两层的梯度会累加到同一批行。

优化器

所有嵌入表（输入嵌入、VE、NVE、提示类别嵌入）归入嵌入参数组：AdamW + 单独学习率、无权重衰减；λ 和门控也一起训练。

参数口径

VE 表不计入 N / N_a，也不产生矩阵乘 FLOPs；但它是真实显存，查表的访存时间会计入 EvalTime。

⑤ 怎么用：混合公式

v = λ0·(W_v·h) + λ1·(g ⊙ VE[x_t]) + λ2·(g ⊙ NVE₂) + λ3·(g ⊙ NVE₃) g = 2σ(W·h[:12]) # 每个 KV 头、每种来源一个门；初始 g = 1 λ 每层 4 个可学习标量，初值 0.5 混合后 reshape 成 [B, 头数, L, 128] → 因果注意力
VE 只负责“当前 token 身份”；局部上下文由下一节的 NVE 负责。两者是两份独立查询，分别用 λ₁ 与 λ₂/λ₃ 加权，不是拼在一起再算。

④ 怎么训练更新

初始化与反向

N(0, 0.02) 随机初始化；梯度只回传到本 batch 命中的那些行（未命中行不变）。全模型所有 VE 层共用这一套表，梯度从各层累加到相同行上。

优化器与口径

归入嵌入参数组（AdamW + 单独学习率、无权重衰减）；可以给 NVE 单独学习率，但这次没启用。表不计 N / N_a、不计 FLOPs，但占显存、查表时间计入 EvalTime。

⑤ 怎么用 + 撞桶

v = λ0·(W_v·h) + λ1·(g ⊙ VE[x_t]) + λ2·(g ⊙ NVE₂[hash(x_{t-1}, x_t)]) + λ3·(g ⊙ NVE₃[hash(x_{t-2}, x_{t-1}, x_t)]) g = 2σ(W·h[:12])，每个 KV 头、每种来源一个门；初始 g = 1
撞桶：不同的 n-gram 完全可能落到同一行（哈希没有指纹校验）。它们会读到同一段向量，训练时梯度也相加。 4 组独立哈希的作用是把一次碰撞的影响限制在 kv/4 个通道上，而不是整段 kv；4 组同时撞的概率更低。

② 怎么查：哈希 + 指纹校验

对每个阶 n（2/3/4/6/10/20）： hash = mix( x_t·m0 ⊕ x_{t-1}·m1 ⊕ … ⊕ x_{t-n+1}·m_{n-1} ⊕ (n<<42) ) # m0 乘当前 token，m1 乘前一个 …（与建表脚本一致） slot = hash & (2^bits − 1) # 取低位作为槽号 fp = (hash >> bits) & 0xFFFF # 取高位作为 16 位指纹 命中条件：表里的指纹 == fp 且 后继 token 槽非空 命中后得到：(后继 token, 类别) 15 列分别查 → 最多 15 个 (token, 类别)；没有命中的列贡献 0

和 NVE 的区别：hint 表有 16 位指纹校验，能拒绝大部分哈希冲突；NVE 没有指纹，撞了就用同一行。hint 的阶到 20，NVE 只到 3。

类别 = 7 个次数桶 × 6 个纯度桶 = 42 类；同一列的不同 n-gram 共享这个类别的信任度。

④ 一次查表 → 三处使用

第一步：拼提示向量 H

H = Σ_{命中的列 c} [ (1 + amount[cls_c]) · E[tok_c] + feat[cls_c] ] amount：该类别的“信任度缩放”（可学习，初始 0） feat ：该类别的偏置向量（可学习，初始 0） E ：输入嵌入表（与普通 token 共享同一张表）

同一个 token 被多列命中时，它的 E[tok] 会被加多次（每列用各自的类别参数）。

第二步：三处注入

① 输入： h⁰ ← h⁰ + s_in · H ② 输出前： h ← h + s_out · H ③ logit： logits[t, tok_c] += score[cls_c] s_in / s_out：两个可学习标量，初始 0 score[cls] ：每个类别一个可学习标量，初始 0

所以训练第 0 步，整个 hint 分支贡献恒为 0，模型等价于完全不用提示。

三处注入的完整时间线

input_ids [B, L] │ ├─ 查表一次：15 列 → H、hint_scores ▼ E[input_ids] + s_in · H ← ① 输入嵌入 ▼ L 层 Transformer（中间不再加 hint） ▼ 最终 RMSNorm │ ├─ h + s_out · H ← ② 输出层之前 ▼ 输出层（可能先 head_proj 再 lm_head） ▼ logits [B, L, 49152] │ ├─ logits[t, tok_c] += score[cls_c] ← ③ logit 加分 ▼ softmax / 交叉熵

三处共用一次查表结果：H 复用两次，logit 用的是同一批候选 token。位置 t 的提示来自“以 x_t 结尾的 n-gram 后继”，所以三处都在为预测 t+1 服务。

① 输入嵌入：h⁰ += s_in · H

加在哪：第 1 层之前，和 token 嵌入直接相加。

inputs_embeds = E[input_ids] + s_in · H E[input_ids] [B, L, h] H [B, L, h] s_in 标量（hint_mix[0]，初始 0）

为什么加在这里：提示从第 1 层就进入残差流，后面的注意力、MLP 都能间接使用；相当于提前告诉模型“这个词后面通常接什么”。

形状（1e19）：E[input_ids] [B,3072,1152]、H [B,3072,1152]、s_in 标量。

② 输出层之前：h += s_out · H

加在哪：所有 Transformer 层跑完、最终 RMSNorm 之后，输出层之前。

h = RMSNorm(h_L) h = h + s_out · H logits = W_out · h # 或先 head_proj 再 lm_head

注意：这不是每层注意力的输出前。每层 V 里加的是 VE / NVE（逐层、逐 token）；hint 是模型级，只在入口和出口各加一次。中段缩短时也不会重新查 hint。

s_in 和 s_out 是两个独立标量，模型可以学“入口少信一点、出口多信一点”，或反过来。

③ logit 加分：logits[t, tok_c] += score[cls_c]

加在哪：输出层算出 logits 之后、softmax / 交叉熵之前。

logits[t, tok_k] += score[cls_k] score[cls]：每个类别一个可学习标量（631 个），初始 0 同一个 token 被多列命中 → 分数相加（scatter_add） 没命中 → 加 0 没有矩阵乘，只改候选 token 所在的列

和输出前注入的区别：输出前是 h 维隐空间的向量，经过 W_out 后影响全部 logits；logit 加分是 49152 维词表空间里的标量，只改那 15 个候选列。

为什么分成三处

入口：进入表示 → 影响所有层 出口：进入最终隐状态 → 离预测近 logit：直接改候选分数 → 最直接 s_in / s_out / score 分别学习每一处的信任程度

初始化时 amount = feat = score = 0、s_in = s_out = 0，所以第 0 步整个 hint 分支贡献为 0，模型等价于完全不用提示。注意 H 本身不为 0，只是被 s = 0 乘掉了。

梯度会流向哪里

  • 被提示 token 的输入嵌入 E[tok] 行：收到额外梯度（同一 token 多列命中就多份）；
  • amount / feat / score：每个类别一组参数，只更新被命中的类别；
  • s_in / s_out：两个全局标量，所有位置共享；
  • 主干：通过残差流正常反传；
  • hint 表本身：没有参数、没有梯度，不进优化器和 state_dict。

一个 3 维数值例子（假设 h=3）

某个位置命中 2 列：列 0（token 123，类别 5）、列 8（token 123，类别 12）。

E[123] = [0.2, -0.1, 0.4] amount[5] = 0.0 feat[5] = [0, 0, 0] amount[12] = 0.5 feat[12] = [0.01, 0.02, -0.01] 列 0：1.0 × E[123] + feat[5] = [0.2, -0.1, 0.4] 列 8：1.5 × E[123] + feat[12] = [0.31, -0.13, 0.59] H = [0.2,-0.1,0.4] + [0.31,-0.13,0.59] = [0.51, -0.23, 0.99] 假设学到的 s_in=0.1、s_out=0.2： 输入：h⁰ += 0.1 × H = [0.051, -0.023, 0.099] 输出：h += 0.2 × H = [0.102, -0.046, 0.198] logit：logits[123] += score[5] + score[12]

同一个 token 被两列命中时，向量加两次、logit 分数也加两次——这正是“多阶都指向它”时提示更强的来源。

⑥ 它不更新，为什么还能影响训练

梯度怎么走

表没有参数、没有梯度，但查到的 (token, 类别) 参与前向，所以梯度会流向：

  • 被提示 token 的输入嵌入 E 行（额外梯度）
  • 提示类别嵌入 amount / feat / score
  • 输入/输出两个强度标量 s_in / s_out
  • 以及整条主干的所有参数

它相当于一个固定的先验特征，模型学的是“信不信、信多少”。

训练用哪份表

训练时用“只用 75% 语料统计、且与训练实际使用的 25% 语料互不重叠”的表——否则模型会过度信任提示，到评测就失效。

提交 / 推理时换成“用 100% 训练语料统计”的同结构表；两份表槽位、字段、查询方式完全相同，只是统计来源不同。

训练器会核对两边的划分指纹，防止混用。

⑦ 干什么用：为什么值得占 112 GB

它把“语料级的 n-gram 继续概率”变成零 FLOPs 的额外信息源，补的是模型参数里学不到的稀有/固定搭配：

输入注入：让提示从第 1 层就进入残差流，影响所有层的表示。
输出前注入：在最终表示上再提醒一次，离预测更近。
logit 加分：直接改候选 token 的分数，零矩阵乘、作用最直接。

代价：表约 112 GB、查表访存时间计入 EvalTime；但它的参数不计入 N / N_a、不产生矩阵乘 FLOPs。
