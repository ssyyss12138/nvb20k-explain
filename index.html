模型架构

骨架就是 Qwen3 那套 decoder-only Transformer。四档只改宽度、深度和头数，head_dim 都是 128。

骨架

四档同一套结构

MLP

两矩阵 ReLU²

MLP 用 W_d · ReLU²(W_u · x)，中间维约 2.7h。比 SwiGLU 少一个矩阵，参数和 FLOPs 约为 2/3。

02

Token 压缩技术：16 个 token → 1 个位置

压缩只发生在中间约 60% 的层：前后 20% 还是逐 token，中间把 16 个连续 token 合成 1 个位置，序列从 3072 缩到 192。只降序列长度，h 不变。

① 怎么压：拼接 + 线性投影

在第 s 层（前段最后一层）之后，先留一份全长残差 a = x（[B, 3072, h]），然后：

x_pad = 序列前面补 15 个零向量 # [B, 3072+15, h] 每 16 个连续向量拼接成一个 16h 向量 # [B, 192, 16h] z = W_down · concat # [B, 192, h] W_down : [h, 16h]（无 bias 的线性层） 1e19：h = 1152，16h = 18432

第 j 个位置装的是原序列 token 16j−15 … 16j。第 0 块左边补 15 个零。窗口不重叠，也不看未来。

1e19 的数字

原序列3072
压缩后192
每个位置拼接16 × 1152 = 18432
W_down18432 → 1152
窗口 jtoken 16j−15 … 16j

序列长度都是 16 的整数倍；不是的话末尾补零，只影响最后一个位置。

② 压缩后“位置”怎么定：不是新 token id，是块号 j

token id 不变。分词器给的是什么就是什么，压缩不会重新编号。压缩的是隐状态序列，不是 token id。

压缩后是 192 个位置，编号 j = 0 … 191（块号）。每个位置 j 对应原序列 16 个 token，中段里只占 1 个位置：

中段 RoPE 位置 = 块号 j（0 … 191） 中段因果 mask = 192 × 192 的因果矩阵 中段 attention 的“序列长度” = 192

中段 RoPE 用块号 j，因果 mask 是 192×192，attention 的长度也是 192。

③ 怎么恢复：上投影 + 按块切片 + 内容门控 + 残差

中段算完，用 W_up 展开回 3072 个 token：

u = W_up · z # [B, 192, 16h] reshape 成 [B, 192, 16, h] token t 取第 ⌊t/16⌋ 块的第 (t mod 16) 片： u_t = u[⌊t/16⌋, t mod 16] g_t = 2σ( W_out·W_in·RMSNorm(a_t) + β_{t mod 16} ) # 秩 64 x_t = a_t + g_t ⊙ u_t # 加回压缩前残差

展开不是复制。块里 16 个 token 共享同一份摘要，但每个 token 用自己的门 g_t 决定读回多少，再加压缩前的残差 a_t。

为什么能恢复出细节

  • 压缩前的残差 a_t 一直留着，原始信息没丢；
  • 门 g_t 由当前 token 自己算，读多少摘要逐 token 决定；
  • 后段 20% 的层回到全分辨率，继续逐 token 算。

整体就是“下采样 → 低分辨率处理 → 上采样 + 跳连”。

03

VE 表：按当前 token 查表，加进注意力 V

VE（Value Embeddings）给每个 token 的 Value 加一条可学习旁路。q/k 和注意力分数都不动，只改被聚合的 v；查表没有矩阵乘。

干什么用

注意力的输出是 Σ softmax(q·k)·v，v 才是被加权的内容。标准 Transformer 的 v 全来自 W_v·h；VE 额外查一段向量加进 v。

注意力权重再散，每个 token 的 value 里也始终带着自己的身份信息。

用在哪

每层 V 投影之后、分头和因果注意力之前。中段只在块尾 token 查（每 16 个一次）。

和输入嵌入 E 的区别：E 只在输入残差流；每层 V 由 W_v 重新算；VE 是另查表加到 V 上。

② 怎么查：行号就是 token id

普通嵌入查表，不是哈希。

给定位置 t 的 token id x_t，以及它所在的层 i： 1. 找到层 i 绑定的表 g 2. 取表 g 的第 x_t 行 3. 得到一个 kv 维向量 前后全分辨率层：每个 token 都查 中段缩短层：只在块尾 token（第 16j 个）查一次，整块共用

查出来是 kv 维（3e17 是 640，1e19 是 1152）；要逐 KV 头门控就 reshape 成 [KV 头数, 128]。没有哈希、碰撞和指纹。

③ 一个具体例子

3e17 档、token id = 4471、位于第 0 层：

第 0 层绑定表 0（与第 17 层共用） → 取表 0 的第 4471 行：一个 640 维向量 → reshape 成 5 个 KV 头 × 128 → 每头乘门控 g（初始 1） → 按 λ₁ 加进该 token 的 v

如果这个 token 同时被 VE 和 NVE 命中，v 里会加两路向量，分别用 λ₁、λ₂/λ₃ 加权。

④ 怎么训练更新

初始化

表：N(0, 0.02) 随机初始化，和输入嵌入一样；λ 初值 0.5；门控零初始化（初始 g = 1）。

反向传播

梯度从注意力输出回到 v，再回到被查到的行。本 batch 没出现的行不更新。首尾层共用表，梯度会累加到同一批行。

优化器

所有嵌入表（输入嵌入、VE、NVE、提示类别）都进嵌入参数组：AdamW + 单独学习率、无权重衰减。λ 和门控一起训练。

参数口径

VE 表不计入 N / N_a，也不产生矩阵乘 FLOPs；但占显存，查表时间算进 EvalTime。

⑤ 怎么用：混合公式

v = λ0·(W_v·h) + λ1·(g ⊙ VE[x_t]) + λ2·(g ⊙ NVE₂) + λ3·(g ⊙ NVE₃) g = 2σ(W·h[:12]) # 每个 KV 头、每种来源一个门；初始 g = 1 λ 每层 4 个可学习标量，初值 0.5 混合后 reshape 成 [B, 头数, L, 128] → 因果注意力
VE 负责当前 token 的身份，局部上下文交给下一节的 NVE。两路独立查表，不是拼在一起再算。

④ 怎么训练更新

初始化与反向

N(0, 0.02) 随机初始化。梯度只回传到本 batch 命中的行，没命中的不变。所有 VE 层共用一套表，梯度从各层累加到相同行。

优化器与口径

归入嵌入参数组（AdamW + 单独学习率、无权重衰减）。NVE 可以单独设学习率，这次没开。表不计 N / N_a、不计 FLOPs，但占显存、查表时间算进 EvalTime。

⑤ 怎么用 + 撞桶

v = λ0·(W_v·h) + λ1·(g ⊙ VE[x_t]) + λ2·(g ⊙ NVE₂[hash(x_{t-1}, x_t)]) + λ3·(g ⊙ NVE₃[hash(x_{t-2}, x_{t-1}, x_t)]) g = 2σ(W·h[:12])，每个 KV 头、每种来源一个门；初始 g = 1
撞桶：不同 n-gram 可能落到同一行（哈希没有指纹校验），读到同一段向量，梯度也叠加。4 组独立哈希把一次碰撞限制在 kv/4 个通道，4 组同时撞的概率更低。

对 6 个阶（2/3/4/6/10/20），统计每个 n-gram 的后继 token 频次；每个阶按次数保留前 4/4/3/2/1/1 名后继，共 15 列。

② 怎么查：哈希 + 指纹校验

对每个阶 n（2/3/4/6/10/20）： hash = mix( x_t·m0 ⊕ x_{t-1}·m1 ⊕ … ⊕ x_{t-n+1}·m_{n-1} ⊕ (n<<42) ) # m0 乘当前 token，m1 乘前一个 …（与建表脚本一致） slot = hash & (2^bits − 1) # 取低位作为槽号 fp = (hash >> bits) & 0xFFFF # 取高位作为 16 位指纹 命中条件：表里的指纹 == fp 且 后继 token 槽非空 命中后得到：(后继 token, 类别) 15 列分别查 → 最多 15 个 (token, 类别)；没有命中的列贡献 0

和 NVE 的区别：hint 有 16 位指纹校验，能挡掉大部分哈希冲突；NVE 没有指纹，撞了就用同一行。hint 到 20 阶，NVE 只到 3。

类别 = 7 个次数桶 × 6 个纯度桶 = 42 类；同一列的不同 n-gram 共享这个类别的信任度。

③ 完整算例（续）：x_{t-2}=100, x_{t-1}=30, x_t=2（3 阶）

(100,30,2) 的手算过程

3 阶表有 2³⁰ 个槽（bits=30），用 3 个乘数：m0 乘 x_t，m1 乘 x_{t-1}，m2 乘 x_{t-2}。

m0 = 1,692,323,285 m1 = 1,821,802,719 m2 = 995,982,333 t0 = 2 × m0 = 3,384,646,570 t1 = 30 × m1 = 54,654,081,570 t2 = 100 × m2 = 99,598,233,300 key0 = t0 ⊕ t1 ⊕ t2 = 117,048,012,636 key = key0 ⊕ (3 << 42) = 13,311,187,545,948 k1 = key ⊕ (key >> 21) = 13,311,193,789,784 k2 = k1 × 0x6F4B mod 2^64 = 379,249,222,264,735,944 k3 = k2 ⊕ (k2 >> 29) = 379,249,222,902,620,556 = 0x05435d28ac74218c slot = k3 & (2^30 − 1) = 745,808,268 fp = (k3 >> 30) & 0xFFFF = 0x74A2 = 29,858

两张表各查各的：2 阶用槽 70,496,936、指纹 0x05E1；3 阶用槽 745,808,268、指纹 0x74A2。15 列都命中时，最多拿到 15 个候选。

④ 一次查表 → 三处使用

第一步：拼提示向量 H

H = Σ_{命中的列 c} [ (1 + amount[cls_c]) · E[tok_c] + feat[cls_c] ] amount：该类别的“信任度缩放”（可学习，初始 0） feat ：该类别的偏置向量（可学习，初始 0） E ：输入嵌入表（与普通 token 共享同一张表）

同一个 token 被多列命中时，它的 E[tok] 会被加多次（每列用各自的类别参数）。

第二步：三处注入

① 输入： h⁰ ← h⁰ + s_in · H ② 输出前： h ← h + s_out · H ③ logit： logits[t, tok_c] += score[cls_c] s_in / s_out：两个可学习标量，初始 0 score[cls] ：每个类别一个可学习标量，初始 0

训练第 0 步时整个 hint 分支输出 0，模型等于不用提示。

前向里的三次使用

input_ids [B, L] │ ├─ 查表一次：15 列 → H、hint_scores ▼ E[input_ids] + s_in · H ← ① 输入嵌入 ▼ L 层 Transformer（中间不再加 hint） ▼ 最终 RMSNorm │ ├─ h + s_out · H ← ② 输出层之前 ▼ 输出层（可能先 head_proj 再 lm_head） ▼ logits [B, L, 49152] │ ├─ logits[t, tok_c] += score[cls_c] ← ③ logit 加分 ▼ softmax / 交叉熵

三处共用一次查表结果：H 用两次，logit 用同一批候选。位置 t 的提示来自以 x_t 结尾的 n-gram，三处都在预测下一个 token。

① 输入嵌入：h⁰ += s_in · H

加在哪：第 1 层之前，和 token 嵌入直接相加。

inputs_embeds = E[input_ids] + s_in · H E[input_ids] [B, L, h] H [B, L, h] s_in 标量（hint_mix[0]，初始 0）

为什么加在这里：提示从第 1 层就进残差流，后面的层都能用。

形状（1e19）：E[input_ids] [B,3072,1152]、H [B,3072,1152]、s_in 标量。

② 输出层之前：h += s_out · H

加在哪：所有 Transformer 层跑完、最终 RMSNorm 之后，输出层之前。

h = RMSNorm(h_L) h = h + s_out · H logits = W_out · h # 或先 head_proj 再 lm_head

注意：这不是每层注意力的输出前。每层 V 里加的是 VE / NVE；hint 是模型级，只在入口和出口各加一次。

s_in 和 s_out 分开学，入口和出口可以有不同的信任度。

③ logit 加分：logits[t, tok_c] += score[cls_c]

加在哪：输出层算完 logits、softmax 之前。

logits[t, tok_k] += score[cls_k] score[cls]：每个类别一个可学习标量（631 个），初始 0 同一个 token 被多列命中 → 分数相加（scatter_add） 没命中 → 加 0 没有矩阵乘，只改候选 token 所在的列

输出前注入是 h 维向量，经过 W_out 影响全部 logits；logit 加分是 49152 维空间里的标量，只改候选列。
